# RCA — run 3b537e1c-854b-4ac1-bd0b-e954b790671e (odisha-learning-pro)

## Verdict
Build failed at the **`yarn build` (Next.js production build)** step — a **source-code / dependency problem**, NOT a deployment/manifest problem and NOT the pip-cache miss shown in the truncated error excerpt.

## Misleading symptom
The trigger error tail quotes step #0 `restore-pip-cache`: `CommandException: No URLs matched: gs://.../pip-cache.tar.gz`. That is a **harmless cache miss** (no cache object exists yet) and is not what failed the build. The full build log shows the failure is later, at **step #2 `docker-build`, `RUN yarn build`**.

## Actual root cause
`yarn build` failed with webpack compile errors while bundling the API route `./app/api/[[...path]]/route.js`, which imports `./lib/assess-pdf-stamp.js` → the native PDF library **`muhammara`**, plus **`archiver`**.

Webpack tried to bundle Node-native / server-only packages and could not resolve their optional deps:

```
./node_modules/muhammara/node_modules/@mapbox/node-pre-gyp/lib/mock/http.js
  Module not found: Can't resolve 'nock'
./node_modules/muhammara/node_modules/@mapbox/node-pre-gyp/lib/mock/s3.js
  Module not found: Can't resolve 'mock-aws-s3'
./node_modules/muhammara/node_modules/@mapbox/node-pre-gyp/lib/util/s3_setup.js
  Module not found: Can't resolve 'aws-sdk'
Import trace: .../muhammara/lib/index.js -> ./lib/assess-pdf-stamp.js -> ./app/api/[[...path]]/route.js

./node_modules/archiver/lib/core.js
  Module not found: Default condition should be last one
Import trace: ./node_modules/archiver/index.js -> ./app/api/[[...path]]/route.js

> Build failed because of webpack errors
executor failed running [/bin/sh -c yarn build]: exit code: 1
```

`muhammara` (and its `@mapbox/node-pre-gyp` loader) and `archiver` are native/server-only modules. They must run only on the Node server runtime and must **not** be traced/bundled by the webpack client/server compiler. This is a new failure: the immediately prior run (9117d983, ~1h earlier) built fine — the muhammara/archiver usage in `assess-pdf-stamp.js` / the API route was introduced in this source revision.

## Fix (owner: E1 / source code — not a manifest fix)
Mark these as server-external packages so Next.js loads them at runtime via require() instead of bundling them. In `next.config.js`:

- **Next.js 15+:**
  ```js
  const nextConfig = {
    serverExternalPackages: ['muhammara', 'archiver'],
  };
  ```
- **Next.js 13/14:**
  ```js
  const nextConfig = {
    experimental: { serverComponentsExternalPackages: ['muhammara', 'archiver'] },
  };
  ```

If errors persist for the mapbox mock deps specifically, additionally externalize/ignore them in the webpack config, e.g.:
```js
webpack: (config, { isServer }) => {
  if (isServer) {
    config.externals = [...(config.externals || []), 'muhammara', 'archiver'];
  }
  config.resolve.fallback = { ...config.resolve.fallback, 'aws-sdk': false, 'mock-aws-s3': false, nock: false };
  return config;
},
```

Confirm the route that uses these runs on the Node runtime (`export const runtime = 'nodejs'` in `app/api/[[...path]]/route.js`), which it must for native PDF/zip libs.

The build log evidence is complete and unambiguous, so no sandbox run was needed to identify the cause. After E1 applies the next.config.js change, re-trigger the deploy.
