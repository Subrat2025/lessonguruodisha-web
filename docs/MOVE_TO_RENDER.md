# Launching Lesson Guru Odisha v1.6 on the new platform

The new website + backend runs on **Render**, and the database on **MongoDB Atlas** (Mumbai).
**Nothing is deployed to Emergent any more.** Emergent is used only once, as the place your
existing data is copied from. After the switch you can shut it down.

Teachers notice nothing:
- the address stays **lessonguruodisha.in**;
- they log in as before;
- Premium and their saved work carry over;
- both Android apps (Play Store and Direct) keep working without an update.

Plan on about **3–4 hours of your time**, spread over two days:
- **Day 1:** set up and test on a temporary Render address.
- **Day 2:** the switch, about 30 minutes, late at night.

---

## What's in the website zip (`LessonGuruOdisha-website-v1.6.0.zip`)

- The full v1.6 website and backend:
  - one-page lesson PDFs with teacher and headmaster signatures;
  - no buying shown in the Play Store app;
  - buying kept in the Direct app and the browser;
  - Cloud Library, account deletion and OTP Health.
- `render.yaml` + `Dockerfile`: create the whole setup on Render in one click, including the 5 scheduled jobs.
- `scripts/copy-database.mjs`: copies all data into Atlas and checks the counts.
- `public/app/LessonGuruOdisha-Direct.apk`: the Direct app. Teachers download it from **https://lessonguruodisha.in/app/LessonGuruOdisha-Direct.apk**.
- Safety switch `BACKGROUND_JOBS_DISABLED=1`: the new server starts **paused**, so no duplicate WhatsApp messages are sent before the switch.

## Step 1: Put the code on GitHub (private)

The easiest way: create an **empty private repository** named `lessonguruodisha-web` on github.com (no README) and send me its name. I'll upload the code.

Or yourself, with GitHub Desktop:
1. **New repository** `lessonguruodisha-web`.
2. Unzip the website zip and copy everything inside `LessonGuruOdisha26102026-main/` into the repository folder.
3. Commit to **main** → **Publish** (keep **Private**).

## Step 2: Create the database on Atlas (Mumbai)

1. **Create cluster:** M10 (or Flex), **AWS · Mumbai (ap-south-1)**, name `lessonguru`.
2. **Database Access → Add user:**
   - `lessonguru_app`;
   - autogenerated password (save it);
   - role **Read and write to any database**.
3. **Network Access → Allow access from anywhere (0.0.0.0/0).** Render has no fixed IP; the strong password protects the database.
4. **Connect → Drivers** → copy the address and put your password in it:
   `mongodb+srv://lessonguru_app:<password>@lessonguru.xxxxx.mongodb.net/?retryWrites=true&w=majority`
   This is your **Atlas URL**.
5. (M10) **Backup → Continuous Cloud Backup: On.**

## Step 3: Get your settings from Emergent (read only)

In Emergent, ask its agent:

> Show me all environment variables of the deployed (production) app, values included, and the production MongoDB connection string.

Save the list privately. The most important values:
- `MONGO_URL` / `DB_NAME`: where the existing data is;
- `JWT_SECRET`: it **must stay exactly the same**, or every teacher is logged out;
- the Razorpay, WhatsApp (BULKY…), Gemini and Cloudflare R2 keys.

## Step 4: Create everything on Render (one click)

1. Render → **New + → Blueprint** → connect GitHub → `lessonguruodisha-web` → branch `main`.
2. Render shows **lessonguru-web** + 5 **cron-…** jobs and asks for a few values:
   - `MONGO_URL`: your **Atlas URL**;
   - `DB_NAME`: the same name as in step 3;
   - `JWT_SECRET`: **exactly** the old value;
   - Razorpay, BULKY, Gemini and R2 keys from step 3.

   Click **Apply**.
3. **lessonguru-web → Environment → Add from .env**: paste the rest of the step 3 list, but **delete these lines first**:
   - `MONGO_URL`
   - `DB_NAME`
   - `NEXT_PUBLIC_BASE_URL`
   - `BACKGROUND_JOBS_DISABLED`
   - `WEBHOOK_CRON_SECRET`

   Then **Save, rebuild and deploy**.
4. Wait 10–20 minutes until the status shows **Live**. The site runs at **https://lessonguru-web.onrender.com**.

## Step 5: Copy the data (test copy)

Render → **lessonguru-web → Shell**, then run these two commands. Paste your values for the parts in `< >`.

```
SOURCE_MONGO_URL="<old production MONGO_URL from step 3>" SOURCE_DB="<DB_NAME>" TARGET_MONGO_URL="$MONGO_URL" TARGET_DB="$DB_NAME" node scripts/copy-database.mjs --dry-run
SOURCE_MONGO_URL="<old production MONGO_URL from step 3>" SOURCE_DB="<DB_NAME>" TARGET_MONGO_URL="$MONGO_URL" TARGET_DB="$DB_NAME" node scripts/copy-database.mjs
```

- The first command (`--dry-run`) only lists what is there. The **`users` line must show about 17,000+**.
- The second command copies everything and ends with **"All document counts match."**
- The old database is only **read**, never changed.

**If Render can't connect to the old database** (Emergent keeps it private): ask Emergent's agent to run the **same command** on their side, with `TARGET_MONGO_URL` set to your Atlas URL. Or ask Emergent support for a database export (`mongodump`) and send it to me; I'll load it into Atlas. You still change nothing on Emergent.

## Step 7: The day before the switch

1. Render → lessonguru-web → **Settings → Custom Domains → Add** `lessonguruodisha.in` and `www.lessonguruodisha.in`. Note the DNS records Render shows.
2. At your DNS provider, **write down the current records** (for rollback), then set their **TTL to 60–300 seconds**.

## Step 8: Switch day (late at night, about 30 minutes)

1. **Final copy:** run the step 5 copy command again, adding `--replace` at the end. Wait for **"All document counts match."**
2. **Point the domain to Render:** replace the `lessonguruodisha.in` and `www` records with Render's. Then press **Verify** in Render. HTTPS turns on automatically.
3. **Turn on background jobs:** Render → lessonguru-web → Environment → **delete `BACKGROUND_JOBS_DISABLED`** → Save and deploy. WhatsApp campaigns, the message queue and the 5 scheduled jobs start.
4. **Stop the old site:** in Emergent, **stop/pause the deployment**. Don't delete it yet; it's your backup.
5. **Check:**
   - open lessonguruodisha.in on your phone and in both apps;
   - log in, open a lesson, download a PDF;
   - Render **Logs** show teachers arriving.
6. **Next morning:**
   - compare the Razorpay dashboard payments since the final copy with **Admin → Revenue**;
   - restore any missing one with **Admin → 🔄 Subscription Recovery**.

Razorpay, BulkyMarketing and Google settings stay as they are, because the domain doesn't change.

## If something goes wrong

Put the DNS records back to the values you wrote down, and restart the Emergent deployment. Data created on Render in the meantime can be copied back with the same script, **only with my help**. After 7 good days, delete the Emergent project.

## Updating in future

- **Code:** push to `main` on GitHub. Render rebuilds and deploys by itself in about 10 minutes, with no downtime. If a build fails, the old version keeps running.
- **Rollback:** lessonguru-web → **Events** → an earlier deploy → **Rollback**.
- **Settings:** lessonguru-web → **Environment**. After changing a `NEXT_PUBLIC_…` value, use **Manual Deploy → Clear build cache & deploy**.
- **New app version:** I build the Play `.aab` (upload to Play Console) and the Direct `.apk`. Replace `public/app/LessonGuruOdisha-Direct.apk` in the repository so the download link always gives the newest one.
- **Backups:** Atlas → cluster → **Backup** (restore to any minute with M10).
- **Health:** Render → **Metrics** (if memory stays near 2 GB, move to the **Pro** plan); Atlas → **Monitoring**.
