# Cloud Library — backend

Every teacher gets a private cloud folder for PDFs and documents. The Android app (v1.1+)
backs up each file the teacher downloads, and teachers can also upload files, open them on
any phone, share time-limited links, rename, star and delete them.

It is part of the existing Next.js backend and MongoDB database. It doesn't need a new
server: deploying this code is enough.

## Where things live

| Piece | Location |
|---|---|
| Service (validation, quotas, storage, signed links) | `lib/cloud-files.js` |
| API routes | `app/api/cloud/files/**/route.js` (they take precedence over the `[[...path]]` catch-all) |
| File metadata | MongoDB collection `cloudFiles` |
| File bytes | **Cloudflare R2 private bucket** via `lib/storage.js` (key `cloud/<userId>/<fileId>.<ext>`). If R2 isn't configured, the bytes go into MongoDB collection `cloudFileChunks` (1 MB chunks) |
| Tests | `tests/cloud/` |

Indexes are created automatically on first use:

- `cloudFiles`: `{id}` unique, `{userId, createdAt}`, `{userId, sha256}`
- `cloudFileChunks`: `{fileId, n}` unique

### `cloudFiles` document

```js
{ id, userId, name, ext, mime, kind: 'pdf'|'image'|'doc', bytes, sha256,
  storage: 'r2'|'db', key, source: 'app-auto'|'app-upload'|'upload'|'web', sourcePath,
  starred, tags: [], linkVersion, openCount, lastOpenedAt, createdAt, updatedAt }
```

## Configuration

Storage uses the same R2 settings as the rest of the site (`R2_GATEWAY_URL` + `R2_GATEWAY_SECRET`,
or the direct `R2_*` keys). There are no Cloudinary paths and no `STORAGE_WRITE` flag. This
feature is new and writes straight to the **private** bucket.

| Env var | Default | Purpose |
|---|---|---|
| `CLOUD_FILES_BACKEND` | `auto` | `auto` = R2 when configured, otherwise MongoDB. `r2` = require R2. `db` = always MongoDB |
| `CLOUD_LINK_SECRET` | `JWT_SECRET` | HMAC key for signed links. Set it so rotating `JWT_SECRET` doesn't break share links |
| `NEXT_PUBLIC_BASE_URL` | — | Origin used in generated links (already set on the site) |

Limits can be changed without a deploy. Insert or update this document in `settings`:

```js
{ key: 'cloud_files', value: { freeMb: 100, premiumMb: 2048, maxFileMb: 25, enabled: true } }
```

Premium means the same rule as the main API: `subscription.status === 'active'` and the expiry
is in the future.

## API

All endpoints take `Authorization: Bearer <em_token>`. They apply the same single-device
session check as the main API: a token from a replaced session gets `401 SESSION_REPLACED`.
Errors look like `{ error: "<message for the teacher>", code: "<CODE>" }`.

| Method & path | Body / query | Returns |
|---|---|---|
| `GET /api/cloud/files` | `q`, `kind=pdf\|image\|doc`, `starred=1`, `sort=new\|old\|name\|size`, `limit≤100`, `skip` | `{ files, total, usage }` |
| `POST /api/cloud/files` | multipart `file` (+`name`, `source`, `sourcePath`) **or** JSON `{ dataUrl, name, source, sourcePath }` | `201 { file, usage }`, or `200 { duplicate: true }` when the same bytes are already saved |
| `GET /api/cloud/files/:id` | — | `{ file }` |
| `PATCH /api/cloud/files/:id` | `{ name?, starred?, tags?, revokeLinks? }` | `{ file }` |
| `DELETE /api/cloud/files/:id` | — | `{ ok, usage }` (removes the bytes too) |
| `POST /api/cloud/files/:id/link` | `{ purpose: 'open' }` (15 min) or `{ purpose: 'share', hours: 1–168 }` (default 72 h) | `{ url, expiresAt }` |
| `GET /api/cloud/files/:id/download` | Bearer token **or** `?t=<signed link>`; `dl=1` forces a download | the file (PDFs and images open inline) |

`usage` = `{ bytes, count, quotaBytes, maxFileBytes, plan, upgradeQuotaBytes }`.

Error codes: `UNAUTHORIZED`, `SESSION_REPLACED`, `NO_FILE`, `EMPTY_FILE`, `FILE_TOO_LARGE` (413),
`QUOTA_EXCEEDED` (413), `UNSUPPORTED_TYPE` (415), `RATE_LIMITED` (429, more than 60 uploads per
hour), `NOT_FOUND`, `LINK_INVALID` (410), `DISABLED` / `STORAGE_UNAVAILABLE` (503).

## Security

- Files are private to their owner. Every query is scoped by `userId`, so another teacher's
  file returns 404.
- The type is detected from the file's content, never from the name or the client's claim.
  Allowed types: PDF, PNG, JPG, DOCX, XLSX, PPTX, ZIP. HTML and scripts are rejected.
- Bytes are never served from a public URL. Downloads stream through the API with
  `Cache-Control: private, no-store` and `X-Content-Type-Options: nosniff`.
- Signed links use HMAC-SHA256 and expire. Share links last at most 7 days. Revoking a file's
  links (`PATCH revokeLinks: true`) or deleting the file invalidates every link to it.
- Storage keys are generated by the server. User input never reaches a storage path.

## Running the tests

The tests call the real route handlers. MongoDB is replaced by an in-memory fake, and R2 by a
fake when `TEST_FAKE_R2=1`. They need a folder whose `node_modules` contains `next@14`, `uuid`
and `jsonwebtoken`. The site's own install works:

```bash
cd tests/cloud
TEST_DEPS=../.. node --import ./register.mjs --test cloud-files.test.mjs                   # MongoDB storage
TEST_FAKE_R2=1 TEST_DEPS=../.. node --import ./register.mjs --test cloud-files.test.mjs    # R2 storage
```

The 13 cases cover: login required, replaced sessions, multi-chunk upload, de-duplication,
the JSON upload path the app uses, type rejection, list/search/filter, exact-bytes download
with Odia filenames, isolation between teachers, signed links (tampered, wrong file, forged
expiry), rename/star/revoke, size and quota limits, and delete freeing space.

Not done yet: a page on the website itself. Teachers manage files in the Android app.
